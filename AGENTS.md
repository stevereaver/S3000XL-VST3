# Local verification

- Read `BUILD.md` for the supported Windows build workflow.
- In this workspace, `build/CMakeCache.txt` points to `C:/mame-s3000xl` and `C:/juce-s3000xl`, not the sibling dependency checkouts. Inspect the configured dependency sources when tracing compiled behavior.
- CMake is installed but may not be on PATH. Verified PowerShell build command from the repository root:
  ```powershell
  & "C:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe" --build build --config Release --target S3000XL-VST_VST3 --parallel 2
  ```
- This uses the existing VS 2022 BuildTools/v143 configuration. Do not change toolchains or rebuild MAME just because CMake is missing from PATH.
- Run `git diff --check` and validate `STATE.json` after edits. A successful build does not verify sample playback: retest sine and loaded samples in the DAW at multiple host block sizes.
- Audio regression case: 44.1 kHz, 2048-frame host blocks, Internal Buffer 512. The old producer threshold allowed only an approximately 882-frame MAME chunk before sleeping, producing 1166-frame silence gaps per host block. Preserve the host-block minimum consistently in buffering, MIDI timing, prefill and PDC.
- Wave RAM regression case: the plugin saves OS RAM and Seq RAM on state save and restores them via `pendingRamInjection` on warm boot, but if the DSP wave RAM (32 MiB at `s3000.cpp:dsp_map`) is not saved/restored alongside them, the firmware believes samples are loaded while the L7A1045's wave memory is empty, so panel PLAY produces distortion. The fix exposes wave RAM as the named share `"waveram"` and persists it under `ram_waveram` (zlib-compressed) in `getStateInformation`, then injects it in the same `pendingRamInjection` path. After any change to the S3000XL driver's memory map, rebuild MAME (`msbuild build\projects\windows\mames3000xl\vs2022\mame_s3000xl.vcxproj /p:Configuration=Release /p:Platform=x64`) before rebuilding the plugin.
- DMA/FDC regression case: in the MAME fork (`C:/mame-s3000xl/src/mame/akai/s3000.cpp`), the V53A DMA controller has a single shared EOP output that was wired straight to the FDC's `tc_w`. Every DSP wave-RAM DMA (channel 3) terminal count asserted EOP and aborted in-progress FDC sector reads (`fifo_pos=0`), so the 0x91b0 staging buffer was starved and wave RAM filled with one repeated 512-word block ("brrrrrrr" on playback). The fix gates the FDC TC with channel-1 DACK (`update_fdc_tc`, `m_fdc_eop && !m_fdc_dack1`; firmware uses active-low DACK, command bytes 0x10/0x14). Only channel-1 terminal counts reach the FDC now. Headless verification: `s3000xl.exe s3000xl -flop1 <image> -autoboot_script <lua> -wavwrite <wav>` — loaded-sample wave RAM and captured audio must not show 512-sample periodicity.
